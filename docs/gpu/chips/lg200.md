# LG200 Generation Profile

Values and capabilities of one generation.  Chapters elsewhere describe the
mechanisms; this page holds the numbers, and a future generation gets its own
profile page with the same section structure.

## Identity and scope

| Property | Value |
|----------|-------|
| Generation | LG200 (Loongson GPU, gen 2) |
| Shader instruction variants | 768 machine rows in 12 format families |
| Instruction word | two little-endian 32-bit words (`INST_LO`, `INST_HI`) |
| Driver generations in this family | LG210, LG220, LG300 (not covered here) |

## Pipes

| Pipe | ICMD MOP | Cursor pair | Typical owner | Completion source |
|------|---------:|-------------|---------------|-------------------|
| GPIPE | `0x01` | write/read pair in the command interface | graphics ring (DRM) | GPIPE end-of-pipe |
| BPIPE | `0x02` | write/read pair in the command interface | graphics inner command stream, blits | BPIPE end-of-pipe |
| CPIPE | `0x03` | write/read pair in the command interface | compute queues (KCD) | CPIPE event |
| XDMA | `0x04` | write/read pair in the command interface | linear copy and fill | XDMA event |
| DPIPE / EPIPE | `0x0c` / `0x0d` | present in the interface | decoder/encoder routes owned by LG210 | not assigned on LG200 |

VMID assignment: the kernel/control context owns one VMID; graphics uses the
next three; compute queues use the remaining four.  Compute queue IDs 0-7 are
exposed.

## Address space and execution limits

| Property | Value |
|----------|-------|
| Page-table entry size | 64 bits, four-level walk |
| Shader code size field | 16-bit byte count in the shader-info record; a complete instruction stream is a multiple of 8 bytes |
| Fragment attributes | 32 attribute-map entries |
| Color attachments | 8 surface records; one depth surface record |
| Viewports | 16 viewport records |
| Maximum wave size / VGPR count / SGPR count / LDS size | UNRESOLVED — the shader-info record carries the *allocation* (SGPR size, VGPR size, LDS size) but the architecture maxima are not established here |

## Graphics state

The graphical payload is one 512-dword state object inside a fixed envelope.
State offsets are relative to the first dword of the object.

| State offset | Object |
|-------------:|--------|
| `0x000` | Draw Info |
| `0x030` | Pipe Enables |
| `0x048` | Viewport[0..15] |
| `0x308` | Guardband |
| `0x318` | Line Raster |
| `0x324` | Depth Control |
| `0x334` / `0x338` | Stencil, front / back |
| `0x33c` | Blend Control |
| `0x340` | Blend RT[0..7] |
| `0x360` | Blend Constants |
| `0x370` | Color Buffer[0..7] |
| `0x470` | Depth Buffer |
| `0x4c0` | Shader Config |
| `0x4c8`-`0x4e8` | Per-stage config records |
| `0x4f0` | Fragment Attribute Map[32] |
| `0x530` / `0x538` | Fragment Input / Output Config |
| `0x540` + `0x60*n` | Shader-info slots: VS, HS, DS, GS, SS, PS |

## Shader stages

| Slot | State offset | Shader type value | Role |
|------|-------------:|------------------:|------|
| VS | `0x540` | not assigned | standalone vertex |
| HS | `0x5a0` | not assigned | hull / tessellation control |
| DS | `0x600` | 3 | tessellation evaluation, or the ordinary vertex role |
| GS | `0x660` | 4 | geometry |
| SS | `0x6c0` | 6 | streamout |
| PS | `0x720` | 5 | fragment |

## Instruction families

| Family | Rows | Format families |
|--------|-----:|-----------------|
| Vector ALU | 374 | `vop`, `vop-imm` |
| Scalar ALU | 119 | `sop`, `sop-imm-control` |
| Memory and image | 138 | `tex-buffer`, `flat`, `shared-memory`, `smem` |
| Atomic | 97 | (shared-memory, flat and tex-buffer forms) |
| Control prefix | 20 | `sop-imm-control`, `jump-stack`, `prefix` |
| SIO and export | 17 | `sio-id`, `sio-imm` |
| Interpolation | 3 | `shared-memory` |
